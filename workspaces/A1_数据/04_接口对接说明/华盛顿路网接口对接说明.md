# 华盛顿特区路网接口对接说明

## 1. 接口目标

本次数据处理旨在将 Geofabrik 原始 OSM PBF 数据转换为现有路径规划引擎可读取的 GraphML 格式，无需重新设计 Dijkstra、A* 算法或核心图数据结构。

数据处理流程如下：

`OSM PBF → 机动车道路筛选 → 道路拓扑构建 → 有向 GraphML → osm_loader.py → Graph → 路径规划算法`

## 2. 格式兼容

原始 OSM 数据由 Node、Way 和 Relation 等对象组织，无法直接作为现有路径规划引擎的邻接图使用。

转换程序主要完成：

1. 筛选机动车道路，排除步行道、自行车道等不适用类型。
2. 根据道路端点、共享节点等识别拓扑连接节点。
3. 将道路拆分为带长度、速度和道路类型属性的有向边。
4. 保留道路折线几何，并支持同一对节点之间存在多条道路。
5. 输出符合现有 `osm_loader.py` 读取要求的 GraphML。

现有加载器将 GraphML 转换为项目内部 `Node`、`Edge` 和 `Graph` 数据结构。路径规划算法继续使用已有图接口，无需修改核心搜索逻辑。

## 3. 数据规模与验证

| 项目 | 结果 |
|---|---:|
| 初始转换图节点 | 160,520 |
| 优化后图节点 | 41,570 |
| 删除的冗余独立节点 | 118,950 |
| 有向道路边 | 99,193 |
| 优化后孤立节点 | 0 |
| 最大弱连通分量 | 39,978 个节点 |
| 最大强连通分量 | 39,507 个节点 |

优化仅删除不参与道路连接的独立形状节点，完整道路折线仍由边的 `geometry` 属性保存。

验证程序检查了节点坐标、道路长度、速度、连通性，以及 Dijkstra 和 A* 在指定测试起终点下的路径代价一致性。实际测试中的最优代价均一致，原有 56 项单元测试通过。

## 4. 与公共模块的关系

本次 A1 工作区提交只提供数据、处理程序和对接说明，不直接修改公共的 `api/main.py`、`web/index.html` 或核心算法源码。

其他组员如需使用新数据，可调用现有 `load_graphml()` 读取优化后的 GraphML。前端大路网渲染优化及后端数据源切换属于后续公共模块适配工作，应单独审核和集成。

## 5. 已知限制

- 尚未完整导入 OSM 转向限制 Relation。
- 部分限速使用道路类型默认值。
- 条件性通行、车道级规则仍采用简化处理。
- 部分道路不属于最大连通分量，任意起终点之间不保证均可达。
- 移入 A1 工作区后，原处理脚本的相对路径和项目根目录定位需要核对并适配，不能直接假定原运行命令仍然有效。

完整方法和验证结果参见 `05_文档报告/华盛顿OSM路网数据处理与系统适配说明.md`。
